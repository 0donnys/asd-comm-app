# РАСигры (ASD-Comm-App)

Рабочий прототип мобильного приложения «РАСигры» для развития коммуникативных
навыков у детей с расстройствами аутистического спектра (РАС) через игры.

Сейчас реализованы 4 сценария: **Магазин → Друг → Площадка → Школа**
(открываются по очереди). Ещё три («Поликлиника», «Кафе», «День рождения»)
показаны как «в разработке».

## Как запустить

**Способ 1 (проще):** дважды кликнуть `start.command` — откроется браузер
с приложением. Чтобы остановить, закрой окно терминала.

**Способ 2:** в терминале в папке проекта выполнить:

```bash
python3 -m http.server 8765
```

и открыть <http://localhost:8765>.

## Как перенести на Android

Проект существует в двух видах, и оба используют один и тот же интерфейс:

| Вид | Что это | Данные |
|---|---|---|
| **Android-приложение** (папка `android/`) | настоящий APK: Kotlin + WebView, свой значок и заставка | **база SQLite** на устройстве |
| **Веб-версия** (корень проекта) | PWA, ставится на экран «Домой» | `localStorage` браузера |

### Вариант A. Собрать APK (основной, для сдачи)

Нужен Android SDK и JDK 21. Пошаговая инструкция — в разделе
[«Сборка Android-приложения»](#сборка-android-приложения).

### Вариант B. Показать прямо сейчас по Wi-Fi (быстро, но без офлайна)

1. На компьютере запустить `start.command` (или `python3 -m http.server 8765`).
2. Узнать IP компьютера: `ipconfig getifaddr en0` (например, `192.168.0.111`).
3. Телефон и компьютер должны быть в одной Wi-Fi сети.
4. Открыть в Chrome на телефоне `http://192.168.0.111:8765`.
5. Меню Chrome → «Добавить на главный экран» — появится иконка как у приложения.

⚠️ По обычному `http://` (не `localhost`) Chrome **не включает офлайн-режим** и не
предлагает «Установить приложение»: service worker работает только на защищённом
соединении (HTTPS). Сам сайт при этом полностью открывается.

### Вариант C. Установка веб-версии с офлайном (HTTPS-хостинг)

Нужен любой бесплатный хостинг по HTTPS. Проще всего — **Netlify Drop**, регистрация не нужна:

1. Открыть <https://app.netlify.com/drop> на компьютере.
2. Перетащить в окно папку проекта (целиком, вместе с `index.html`, `sw.js`, `assets`).
3. Получить ссылку вида `https://ваше-имя.netlify.app` — она работает по HTTPS.
4. Открыть эту ссылку в Chrome на телефоне → меню Chrome → «Установить приложение».
5. Приложение появится на главном экране и будет работать **без интернета**
   (все картинки и озвучка кладутся в кэш при первой загрузке).

Аналогично подойдут GitHub Pages, Cloudflare Pages или Vercel — это тот же статический сайт.

## Сборка Android-приложения

Что нужно один раз установить на компьютер:

```bash
brew install openjdk@21 gradle
brew install --cask android-commandlinetools
```

Затем — Android SDK (компоненты) и приём лицензий:

```bash
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
sdkmanager --install "platform-tools" "platforms;android-34" "build-tools;34.0.0" "emulator" \
  "system-images;android-34;default;arm64-v8a"
yes | sdkmanager --licenses
```

> Берём образ **`default`** (AOSP, ~670 МБ), а не `google_apis` (~1,5 ГБ): в нём уже есть
> WebView, а сервисы Google для этой задачи не нужны.
>
> Если `sdkmanager` качает слишком медленно, пакеты можно скачать напрямую через `curl`
> из `https://dl.google.com/android/repository/` (имена архивов берутся из
> `repository2-3.xml` и `sys-img/*/sys-img2-3.xml`) и распаковать в `$ANDROID_HOME` вручную.

Сборка:

```bash
bash tools/copy-web.sh          # копируем веб-часть в android/app/src/main/assets/www
cd android
./gradlew assembleDebug         # получится app/build/outputs/apk/debug/app-debug.apk
```

Установка на телефон (включена отладка по USB) или в эмулятор:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n ru.asd.commgames.debug/ru.asd.commgames.MainActivity
```

### Эмулятор (если телефона нет)

```bash
sdkmanager --install "system-images;android-34;default;arm64-v8a"
avdmanager create avd -n asd34 -k "system-images;android-34;default;arm64-v8a" -d pixel_6
emulator -avd asd34 &
adb wait-for-device
```

> В проекте уже есть готовый скрипт-обёртка `tools/build-android.sh` со сценариями
> `debug`, `release` и `install` — он сам находит SDK и JDK.

### Release-сборка (подписанный APK)

```bash
# ключ создаётся один раз и лежит в android/release.jks (в репозиторий не попадает)
cd android
keytool -genkeypair -v -keystore release.jks -alias asdcommgames \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass asdcomm2026 -keypass asdcomm2026 \
  -dname "CN=ASD Communication Games, OU=Coursework, O=Student Project, L=Moscow, C=RU"

cat > keystore.properties <<'EOF'
storeFile=release.jks
storePassword=asdcomm2026
keyAlias=asdcommgames
keyPassword=asdcomm2026
EOF

./gradlew assembleRelease      # app/build/outputs/apk/release/app-release.apk
```

`android/app/build.gradle` читает `keystore.properties`: если файла нет — release
собирается без подписи (годится только для проверки), если есть — APK подписывается
автоматически. Пароли в этом файле — учебные, для реального магазина их хранят иначе.

> Проверка `lint` для release отключена (`lint { checkReleaseBuilds false }`):
> `lintVital` пытается скачать свои проверки из сети и на медленном соединении
> надолго зависает. Отдельно проверку можно запустить командой `./gradlew lint`.
> Сборку удобно делать с `--offline`, если зависимости уже в кеше Gradle.

## База данных

В Android-приложении все данные лежат в **SQLite** (`asd_comm.db`):
аккаунты детей, прогресс по сценариям, настройки и id активного аккаунта.
Описание таблиц, связей, ER-диаграмма и SQL — в `docs/database.md` и `docs/schema.sql`.

Приложение работает **полностью офлайн** и не запрашивает разрешение INTERNET:
весь интерфейс, картинки и озвучка лежат внутри APK, данные — в базе на устройстве.

### Что проверено в эмуляторе (Android 14, API 34)

- `./gradlew assembleDebug` → `app-debug.apk` (≈16 МБ) и
  `./gradlew assembleRelease` → **`app-release.apk` (≈15 МБ, подписан)** — обе сборки
  устанавливаются и запускаются без ошибок.
- Release-APK подписан ключом `android/release.jks`
  (SHA-256 сертификата `4A:9A:21:67:E0:51:B3:B5:EA:F3:08:56:29:0A:AE:A2:3D:AD:AC:7C:1A:33:81:2B:15:2F:AA:AC:52:F3:74:23`),
  package `ru.asd.commgames` (без `.debug`), в APK 659 файлов интерфейса и озвучки.
- Название приложения на рабочем столе — **«РАСигры»**, иконка — белая буква **«А»
  на красном фоне** (adaptive-icon для Android 8+ и PNG-иконки для более старых версий).
- У приложения **нет разрешений**, кроме служебного авто-разрешения AndroidX
  (в `dumpsys package` нет `android.permission.INTERNET`).
- Регистрация ребёнка → запись появилась в таблицах `accounts` (1 строка) и `settings` (4 строки).
- Полное прохождение всех 4 сценариев (автотест через Chrome DevTools Protocol,
  `tools/cdp.py`) и на debug-, и на release-сборке: «Магазин» 21/0, «Друг» 17/0,
  «Площадка» 14/0, «Школа» 33/0 — везде **3 звезды**, 0 ошибок; прогресс сохранён
  в `progress` (4 строки). Отдельно проверен мужской пол: тексты с «прошёл / оделся».
- Мульти-аккаунт: второй ребёнок видит **пустой** прогресс, у первого он сохраняется.
- Выход и удаление аккаунта: **неверный** код блокируется, **верный** — выполняет действие;
  при удалении аккаунта его прогресс удаляется каскадом.
- Кнопка «Назад»: в игре → пауза, на паузе → продолжение, в финале → меню, в меню → выход.
- Сцена в игре держит **постоянную высоту** на всех шагах (285 px при экране 412×818):
  при выборе вариантов картинка не «прыгает» и не накладывается сама на себя.
  Эмодзи-заглушка персонажа скрыта, пока не загрузилась иллюстрация.
- В настройках (⚙) есть кнопка **«⏻ Закрыть приложение»** — приложение завершается
  и открывается рабочий стол устройства.
- Авиарежим (сети нет): холодный запуск и полное прохождение сценария работают.
- В `logcat` нет `FATAL EXCEPTION`, `AndroidRuntime` и `ANR`; консоль WebView чистая.

Проверить базу вручную на подключённом устройстве/эмуляторе (весь запрос берём в кавычки,
иначе `;` разорвёт команду на стороне `adb shell`):

```bash
adb shell "run-as ru.asd.commgames.debug sqlite3 -header -column databases/asd_comm.db 'SELECT * FROM progress;'"
```

## Аккаунты

На одном устройстве может быть несколько аккаунтов (например, для брата и сестры).
У каждого — свой профиль, прогресс и звёзды; настройки (звук, озвучка, анимации) общие.

При первом запуске приложение проводит знакомство (5 шагов):

1. имя ребёнка и почта взрослого;
2. код подтверждения из письма (в прототипе письмо не отправляется реально —
   код показывается на экране в «демо-режиме», есть кнопка «открыть письмо»);
3. выбор пола — **девочка** или **мальчик**;
4. выбор смайлика-аватара;
5. готово.

Если аккаунтов уже несколько, при запуске открывается экран **«Кто играет?»**
с кнопкой **«➕ Добавить ребёнка»**. Вход в аккаунт с тем же именем и почтой
возвращает прежний прогресс.

Имя, почта, пол и аватар хранятся на устройстве: в Android-приложении — в базе
SQLite (таблица `accounts`), в веб-версии — в `localStorage`.
От пола зависят иллюстрации персонажа и окончания реплик («оделась / оделся»).

### Выход и удаление

В настройках (⚙) есть строка текущего аккаунта и две кнопки:

- **«🚪 Выйти из аккаунта»** — возвращает на экран «Кто играет?», прогресс сохраняется;
- **«🗑 Удалить аккаунт»** — полностью удаляет аккаунт вместе с прогрессом.

Оба действия подтверждаются **кодом из письма** — так ребёнок не выйдет и не удалит
аккаунт случайно. Удалить чужой аккаунт можно и прямо на экране «Кто играет?»
(кнопка 🗑 на карточке).

Ещё в настройках есть кнопка **«⏻ Закрыть приложение»** (только в Android-версии):
она завершает приложение и возвращает на рабочий стол устройства.

Служебная строка **«🗄 База данных · SQLite …»** по умолчанию **скрыта** — она не нужна
ребёнку. Чтобы показать её (например, на защите), нажмите **5 раз** на заголовок
«Настройки». Повторные 5 нажатий снова прячут строку.

## Как добавить новый сценарий

1. Создать `data/scenarios/<id>.js` по образцу `shop.js`.
2. Подключить файл в `index.html` (перед `js/engine.js`).
3. Добавить запись в массив `SCENARIOS` в `js/app.js`.
4. Добавить реплики в `data/voices.json` и выполнить `python3 tools/make-voices.py`.

## Озвучка

Все реплики заранее озвучены мягким женским голосом
**ru-RU-SvetlanaNeural** (нейросетевой, edge-tts) и лежат в `assets/audio/*.mp3`.
Если файла нет — приложение автоматически использует системный TTS браузера.

Перегенерировать озвучку (нужен интернет; при первом запуске движок
установится сам в `tools/.venv`):

```bash
python3 tools/make-voices.py
```

Запасной вариант без интернета — системный голос macOS Milena:
скрипт переключится на него автоматически, если edge-tts недоступен.

## Иллюстрации

Все фоны, персонажи, карточки предметов и жесты — оригинальные SVG-рисунки
в тёплой осенней палитре, сгенерированные локально (без внешних сервисов):

```bash
python3 tools/make-art.py
```

Скрипт заново создаёт `assets/img/*.svg` и иконки `assets/icons/*.png`,
а затем проверяет, что каждый SVG — корректный XML (битый файл браузер не покажет).
Если картинки не найдены, приложение показывает эмодзи-заглушки.

Посмотреть все картинки разом: откройте `tools/preview-art.html`.
